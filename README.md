# ANANTA IONS — website

Electronics and embedded product engineering. A static, prerendered, six-page
site built for production: no build step in the browser, no CDN runtime, no
framework on the critical path.

```bash
npm install
npm run dev          # http://localhost:5173  — live, with hot reload
npm run build        # -> dist/
npm run serve:dist   # serve the real production build on :8125
npm run qa           # audit that build (needs serve:dist running)
npm run single       # -> dist-preview/ananta-ions.html
```

**Just want to look at it?** `npm run single` bundles the entire site — every
page, the stylesheet, the typeface and the logo — into one self-contained HTML
file you can double-click. No server, no network, no build. Navigation moves to
the hash; everything else behaves exactly as it does in production.

## What it is

| | |
| --- | --- |
| **Pages** | `/`, `/engineering/`, `/capabilities/`, `/projects/`, `/about/`, `/start/` |
| **Build** | Vite, multi-page. Every route is a real HTML document with its own `<head>` |
| **Rendering** | Prerendered to static HTML at build time, then hydrated |
| **Framework** | Preact via `preact/compat` — 10.7 kB gzip against React's 49 kB, same API |
| **First-load JS** | 53 kB raw for the homepage, deferred; the page paints without it |
| **CSS** | 37 kB, one file, hand-written tokens |
| **Fonts** | Inter variable, self-hosted, latin subset, preloaded — one 48 kB file, no third party |
| **Icons** | ~2 kB of inline SVG, drawn for this site. No icon CDN |
| **Dependencies** | Two at runtime (`preact`, `preact-render-to-string`) |

Content is in the document, not assembled after load, so a crawler, an AI agent
or a visitor whose JavaScript never arrives gets the whole site. `npm run qa`
verifies that on every route with scripting disabled.

## Structure

```
src/
  content/      All copy and data. One source of truth, no strings in components
  components/   Layout, Masthead, StackSequence, HardwareBoard, IntakeForm, Trace…
  pages/        One component per route
  styles/       tokens.css → base.css → trace.css → components.css → forms.css
  lib/          pages.js (the route registry), schema.js (JSON-LD)
  entries/      One bundle entry per route, so a page loads only its own code
scripts/
  pages.mjs     Generates the per-route HTML shells from the route registry
  prerender.mjs Renders every page to static HTML
  sitemap.mjs   sitemap.xml + robots.txt
  qa.mjs        The audit gate
  og-image.mjs  Renders the social card from the site's own tokens
  contrast.mjs  WCAG contrast helper for palette work
docs/
  CONTENT-TODO.md      What must be supplied before launch
  QA-REPORT.md         Generated by npm run qa
  design-system/spec/  The original written design-system spec (reference)
```

Routing, `<head>` metadata, canonicals, Open Graph, JSON-LD and the sitemap all
derive from `src/lib/pages.js`, so a page cannot drift out of any of them.

## Design system

Tokens live in `src/styles/tokens.css` in two layers: primitives (raw values)
and semantics (meaning). Components reference only the semantic layer.

The identity is unchanged from the original: deep black ground, one saturated
**gold** `#d4af37` for signal, activation and primary interaction, warm
**copper** `#c66a25` for hardware and physical systems, warm **ivory** for
emphasis, controlled warm-neutral grays for body text. Every text/background
pairing in the UI is verified at WCAG AA or better — `node scripts/contrast.mjs`
checks the palette, `npm run qa` checks the rendered result.

**The ANANTA Engineering Trace** is the site's one proprietary motif: a hairline
conductor carrying signal → power → data → intelligence, terminating in the
square node inherited from the original corner-square mark. It connects scenes,
draws the board diagram, runs the stack rail and the process rail, and arrives at
every call to action. It is drawn, never decorative — a trace only ever connects
two things that are genuinely related. See `src/styles/trace.css`.

## Accessibility

Targets WCAG 2.2 AA, verified per route by axe-core at 1440px and 390px in
`npm run qa`, alongside checks for heading order, landmarks, alt text, one `h1`
per page, target size at nine widths, and keyboard reachability.

The engineering stack is a tab list with roving focus and arrow-key navigation;
scrolling advances it, but choosing a layer stops scroll from overriding you. The
mobile menu is a disclosure with Escape-to-close and focus return. Motion is
opt-out at the token level: `prefers-reduced-motion` zeroes the duration tokens,
so every animation collapses in one place rather than at each call site.

## Content integrity

Nothing on this site asserts a fact that was not in the supplied source material.
Unverified content carries `verified: false` in `src/content/` and renders with a
visible placeholder marker in the same place the claim is made. The intake form
never shows a confirmation for a submission that did not happen.

**This build is technically launch-ready and not content-ready.** See
[docs/CONTENT-TODO.md](docs/CONTENT-TODO.md); `npm run qa` lists every open item.

## Deploying

`dist/` is a plain static folder — upload it anywhere. `.github/workflows/deploy.yml`
builds it, runs the QA gate, and publishes to GitHub Pages; a build that fails
the audit is never published.

Set the production domain in `src/lib/pages.js` (`ORIGIN`) before the first
deploy — canonicals, Open Graph URLs and the sitemap all read from it.
